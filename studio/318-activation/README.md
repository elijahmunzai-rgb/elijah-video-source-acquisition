## Full activation process without misrepresenting success

For **each** of the 318, sequentially:
1. **SOURCE_VERIFIED**: immutable historical SHA/archived Git code exists; record origin/rights.
2. **CAPABILITY_CLASSIFIED**: executable library / external hosted SaaS client / technical assets / instructions / templates / irrelevant. No "running" for pure documents or hosted providers that need paid credits.
3. **SECURITY & LICENSE**: inspect README + full LICENSE + package scripts + dependencies + outbound network + model rights; reject compromised, missing-rights, AGPL-incompatible, paid-only or otherwise unsuitable projects.
4. **INSTALL_TESTED**: isolated short-lived GitHub free runner, no credentials, `npm --ignore-scripts` where appropriate, pinned original code. Don't install 318 executables globally or on the shared Hostinger site.
5. **FUNCTION_TESTED**: execute an actual offline usage case, not only `--help` or reading README. Verify generated source output or real H.264 if tool claims video generation.
6. **PIPELINE_INTEGRATED**: connect in a coherent stage with the actual Film Studio CPU engine; render a representative multi-shot video/asset, not merely compile.
7. **QUALITY_REVIEWED**: licensing and filmed performance, story/shot quality, source pixel realism, audio, no looped "long films", human creative approval. FFprobe 1080p/bitrate is not a creative-quality guarantee.
8. Keep `RUN_BLOCKED` or `REFERENCE_ONLY` for paid API clients, irrelevant projects, or non-executables and give the reason.

Running all 318 *as independent always-on processes* would be wasteful and often impossible. The final professional Studio must be a **composable set of the best usable tools** routed to tasks when needed. "All 318 available to the director" can mean all 318 indexed and safely considered, not 318 background processes.
